### §2.4 — Post-strip cleanup (from PR #24 full-read audit)

Every item verified against `d4d475c`. Zero must-fixes; the strip is invariant-clean. What follows are worth-noting items grouped by priority.

**Verify before onboarding the first tenant (real prod-trap):**

1. **Tenant provisioning must write `fin.tenants` / `fin.holders` / `fin.billing_accounts` synchronously with tenant creation.** `backend/src/billing/events.js:36-48` — `resolveFinTenantContext` returns null when no ACTIVE `fin.tenants` row exists; `emitUsageEvent` then logs a warn and drops the event. A new tenant whose fin-seeding lags will silently lose usage events with no user-visible error. Confirm the seeding path is synchronous before the first live tenant.

2. **Dev-sandbox migration reset needed** (NOT called out in the PR body). Migrations `029_billing_pricing_hierarchy.sql`, `040_billing_notifications.sql`, `042_missing_updated_at.sql` were retroactively rewritten in place. On any existing dev DB where these already ran, the migration runner reads the applied filename from the `migrations` table and won't re-apply — so `public.notification_events` / `notification_deliveries` / `notification_preferences` won't exist, and the dispatcher + `/api/billing/notifications/history` will crash on first call. Fix for dev sandboxes: `DELETE FROM migrations WHERE filename IN ('029_billing_pricing_hierarchy.sql', '040_billing_notifications.sql', '042_missing_updated_at.sql')` then `DROP SCHEMA commercial CASCADE`, then reboot. Production is protected by the zero-live-clients invariant.

**Real bugs, not urgent (fix before real traffic):**

3. **`quota.ledger_entries` reads are full-table scans.** `backend/src/billing/ledger.js:65,78` call `findAll('quota_ledger_entries', predicate)`. `postgres-adapter.js:153-162` implements `findAll` as `SELECT * FROM quota.ledger_entries` + JS `.filter(...)`. Pre-existing pattern (same on the legacy `commercial.ledger_entries`) but the rename made this the sole quota surface, and it grows monotonically. Replace with a `WHERE tenant_id=$1 AND quota_key=$2 AND billing_period=$3` pushdown.

4. **Asymmetric quota locking.** `writeLedgerEntry` (used by `grantAllowance`, `recordTopup`, `recordAdjustment`) inserts through `insert('quota_ledger_entries', row)` and does NOT acquire the `pg_advisory_xact_lock(hashtext(tenant||quota_key||period))` that `quota.record_consumption` takes (migration 289 line 52). A concurrent `grantAllowance` + `recordConsumption` on the same triple can interleave, causing the pre-consumption balance read to miss the grant. Low real risk given usual call patterns; fix by having `writeLedgerEntry` acquire the same advisory lock.

5. **Dead subscription-notification code kept warm.** `notifications/subscription/wire-hooks.js` self-documents that its callers are gone. `sweepTrialEndingNotifications` returns `{ notified: 0 }`. `notifyForHistoryEvent` / `notifyCreditNoteIssued` / `dispatch()` / `preferences.js` / `templates.js` / `deliveries.js` / `/api/billing/notifications/history` have zero live writers, so the route always returns `[]`. All 892 pg tests staying green does not prove any of this executes for a real user event — it currently cannot. Decision: delete the module OR wire a real subscription engine to it as part of §2.2 item 1 (tenant billing UI rebuild). Also `billing/events.js:196` `quotaKeyForAction` — exported through `billing/index.js` with no callers.

**Cosmetic / low value (do when convenient):**

6. Rename `fin/funding/http.js:48` `commercialUnavailable(res)` → `fundingContextUnavailable(res)`. The function name predates the strip; it now serves the "no fin funding context" case and reads misleading.

7. Comment sweep inside `fin/*` for legacy references: `fin/usage/ingest.js:2-3` mentions "commercial.*" and "Stage 3 fin.metered_usage"; `fin/metering/pipeline.js:4` similar; `fin/foundation/advisory-locks.js:4` references `8734281374 (legacy commercial renewal scanner)`.

9. Add a top-of-file banner to `docs/audit/PRE_REBUILD_AUDIT_2026-08-17.md` pointing at DL-244 so any operator following its Stage-13 sections doesn't chase deleted files.

**No action needed:**

10. `fin/admin/exceptions.js#loadExceptions` `ENV_ISOLATION` narrowed from `check_code IN ('R016','R090')` to `check_code = 'R016'` — semantically necessary (R090 gone); safe. If any dashboard alerted on that counter it will now under-count by the R090 dimension, which itself no longer exists.

## §3 — Key architectural decisions locked in during Stages 0-13 + strip

Curated from `docs/design/fin/DECISION_LOG.md` (through DL-083) and commit-message DL rows (DL-089..DL-241). Full DL list is in the log file plus git history.

- **DL-001 / DL-006 / DL-007** — `fin.*` is the only value-movement surface. `usage_events` = facts, not prices.
- **DL-002** — `UNIT_SCALE = 1_000_000`. BIGINT everywhere. Never `Number()` for money.
- **DL-004** — MUTABLE tables: `version` + BEFORE UPDATE trigger + `If-Match` PATCH. APPEND-ONLY tables (`rated_usage`, `ledger_postings`, `financial_audit_events`, `invoice_lines` post-ISSUE, vendor statement lines post-FINALIZE): no `version`, no UPDATE grant.
- **DL-005** — `environment IN ('LIVE','TEST')` on every economic table. Cross-row FKs must match environment.
- **DL-009 / DL-021 / DL-061** — `usage_events` LIST-partitioned by `residency_key`. Composite FKs to `(id, residency_key)`. `__platform__` explicit `FOR VALUES IN`; unknown keys fail closed into DLQ.
- **DL-012 / DL-025 / DL-037 / DL-038** — Strict same-book postings. TRANSFER pair enforced by CHECK + partial UNIQUE + deferred CONSTRAINT TRIGGER at COMMIT.
- **DL-014 / DL-022 / DL-039** — Ledger-tx uniqueness matrix. `idempotency_keys` with `EXPIRED` status. Replay of expired = `IDEMPOTENCY_KEY_EXPIRED`, never re-execute.
- **DL-041 / DL-042 / DL-043** — GDPR erasure = pseudonymise-in-place. FINANCIAL_7Y rows survive. Buyer identity snapshotted on invoices/notes at ISSUE.
- **DL-054** — Lots created at `remaining = granted`. Issue is NOT an allocation. `insertPostingPair` never stamps `lot_id` on ISSUANCE-side postings.
- **DL-076** — `adminMutationLimiter` 10/5min keyed on `req.user.id` + `req.ip`. Skipped when `VITEST` set. This is what remains of 7f/3 wiring after the strip.
- **DL-082 / DL-083** — `rating_hash = SHA-256(canonicalJson(explanation))`. `explanation` IS the preimage. Re-rate deduped by hash.
- **DL-113 / DL-114 / DL-115** (Stage 8) — facility idempotency key includes `cmdName+version`; postpaid CAPTURE R009 fix.
- **DL-206 / DL-216** (Stage 13d) — **operator-only migration convention.** Filenames matching `NNN[letter]_*.sql` (e.g. `260a_`, `290a_`) are skipped by `isAutoMigration` and apply only on an explicit operator endpoint call, not on deploy. Used to gate the freeze migration and the DROP migration behind human confirmation.
- **DL-226 option (a)** (Stage 13f) — `quota.ledger_entries` projection survives the `commercial.*` DROP so tenant-facing quota reads keep working after the schema is gone.
- **DL-239 / DL-240 / DL-241** — `IF EXISTS` on commercial DROP loop; 401 for missing elevated on deprecate route; `targetId` null in freeze audits.
- **Strip decision** (commit `d4d475c`) — with zero live clients, delete the entire cutover module + `commercial.*` migrations rather than carry a dual-schema forever. Codified in the strip's commit message.
